Relatório de Protótipo de Projeto (Escopo) - AgroTech

1. Visão Geral e Atores do Projeto

Componente Descrição Simplificada
Objetivo Principal Realizar a transformação digital das hortas comunitárias gerenciadas pelo Sr. Carlos.
Problema Atual Processos manuais de colheita, estoque, voluntários e doações, gerando perda de dados e falta de histórico.
Solução Proposta Plataforma digital segura e centralizada para garantir controle operacional e eficiência administrativa.
Atores Principais
  • Administrador: Gestão geral do sistema (cadastrar hortas, registrar colheitas, controlar estoques, gerenciar doações e emitir relatórios).
  • Voluntários: Acesso a cronogramas de atividades, confirmação em colheitas e registro de tarefas realizadas.
  • Beneficiários: Recebimento das doações realizadas pela comunidade.
Atores Secundários Fornecedores e parceiros comunitários (stakeholders secundários que influenciam diretamente a operação).

2. Funcionalidades e Relacionamentos (Casos de Uso)

Elemento de Escopo Aplicação no Sistema AgroTech
Funcionalidades Reais Cadastrar Voluntário, Agendar Colheita, Registrar Colheita, Controlar Estoque, Realizar Doação e Emitir Relatórios.
Relacionamento Obrigatório <<include>> O caso de uso "Realizar Doação" inclui obrigatoriamente "Verificar Estoque" para garantir a disponibilidade dos itens antes da conclusão do processo.
Relacionamento Opcional <<extend>> O caso de uso "Agendar Colheita" pode ser estendido por "Enviar Notificação" quando houver voluntários cadastrados para receber mensagens automáticas.

Classe Principal Atributos Principais Métodos Principais Relacionamentos e Multiplicidades
Voluntário idVoluntario, nome, telefone, disponibilidade cadastrar(), atualizarDados(), confirmarParticipacao() Relacionamento N:N com Colheita: Vários voluntários participam de várias colheitas. Usa a classe intermediária Participação (horasTrabalhadas, funçãoExercida).

4. Fluxo do Processo (BPMN - Realizar Doação)

Etapa / Elemento Tipo de Ação no Fluxo Descrição do Comportamento
Início do Processo Evento Inicial O processo começa com o recebimento de uma solicitação de doação.
Validação Tarefa de Sistema O sistema realiza a verificação automática do estoque disponível.
Gateway Exclusivo (XOR) Desvio de Decisão Estoque Insuficiente: O processo é encerrado com o envio de uma notificação de indisponibilidade.
Estoque Suficiente: O sistema avança para a etapa de separação dos itens.
Gateway Paralelo (AND) Ações Simultâneas Permite a execução de duas tarefas simultâneas: atualização automática do estoque e envio de confirmação ao beneficiário.
Fim do Processo Evento Final Ocorre a entrega física da doação e o registro histórico definitivo da operação no sistema.
Fluxos Intermediários Eventos Intermediários Posicionados no fluxo para representar notificações automáticas, confirmações de recebimento e validações internas.
